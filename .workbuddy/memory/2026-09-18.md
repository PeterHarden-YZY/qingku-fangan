## 插件 K=0 真根因：JS SDK fields 以 fieldId 为键，代码按字段名读（下午，铁证修复）

- 现象：用户报插件日志「齐套K:0；回收:$0；报废:$0；全局最优窗口:-」，每次都这样，要反复找修。
- 根因（官方文档铁证，非猜测）：
  1. 飞书 **JS SDK**（base-extension，插件/扩展脚本用的 `@lark-base-open/js-sdk`）的 `table.getRecords()` 返回 `IRecord.fields: { [fieldId: string]: IOpenCellValue }`——键是 **fieldId**（如 `fldXXX`），不是字段名。见 open.feishu.cn 官方文档 + 本地 `node_modules/@lark-base-open/js-sdk/dist/index.d.ts` line 739-744 + lark-base-team.github.io。
  2. 而插件 `src_app.js` 全程 `r.fields["item"]`/`["所属团队"]`/`["model"]` 按**字段名**读 → 线上全部 `undefined` → 库存池空、主表 model/item 空 → K=0、回收$0、报废$0。
  3. **Python 管线不受影响**：它走 lark-cli（HTTP API bitable-v1），fields 键是字段名——所以 Python 结果一直正常（总K=990/1144），只有插件一直 K=0。这是「三端不同源」埋的坑。
  4. **mock 掩盖了 bug**：`mock_host.cjs` 的 `toOpen()` 以字段名为键返回 fields，与真实 SDK 相反 → e2e 一直绿、线上一直挂，排障被致盲。之前 v10/v11 修复（日志字段名/严格模式门控）都没触及这个根因，所以用户反复 K=0。
- 修复（三端同步）：
  1. `src_app.js` + `src/base_script.js`：新增 `loadAllRecords()`（`getFieldMetaList()` 建 id→name 映射，把 fieldId 键转成 name 键再交给业务代码）+ `getParentId()`（父记录 IOpenLink `{recordIds:[]}` 解析，兼容旧 raw 数组）；参数/库存/主表三处读取全部改走 loadAllRecords；父记录 3 处 `Array.isArray` 判断改 getParentId。
  2. `mock_host.cjs`：`getRecords` 改为以 fieldId 为键（`fld_<i>_<name>`）+ 父记录转 IOpenLink，忠实模拟真实 SDK——否则测不出这个 bug。
  3. `run_plugin_test_r4.cjs`：注入/校验逻辑适配 fieldId 键 + IOpenLink。
- 验证（硬证据）：基线组 NO_INJECT=1 总K=**1432**（修复前 0）、HNOFC39DN-LH-US K=10；注入组在途500件30天到货 → K 10→**510**（精确+500）、AMESD01NW-V-US 200件90天 → K=0 超窗正确排除、总K=**1932**、工厂决策 2 条「整单全发(200套)」。
