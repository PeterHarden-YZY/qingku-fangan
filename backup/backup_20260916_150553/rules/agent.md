# agent.md: 库存清库与 BOM 约束分配智能体规范

## 1. 智能体定位 (Role & Goal)
- **Agent 名称**: BOM-ClearAgent (库存清库与 BOM 约束决策智能体)
- **定位**: 跨供应链与财务测算的运筹决策 AI
- **核心目标**: 
  1. 解析产品与组件的 BOM 映射及共享组件库存。
  2. 依据过去30天销量与价格分配权重，对齐套成品进行多方案财务比对。
  3. 自动剥离无法齐套的“长版库存”并强制标记为“组件报废”。并核算报废成本。
  4. 对齐套成品测算【降价卖】、【线下清库（1-2折）】、【激励方案】三种路径的净回收额与成本，推荐最佳清库策略组合。

## 3. 核心算法流程 (Agent Workflow)

### 阶段一：BOM 解构与优先级排序
1. 对于各个有子model的主model，识别共用的子model，把共用一个子model的主model分为一组，为后续该子model库存优先级分配的范围
2. 销售优先级确定：
用过去30天的营收来算没一个主model的优先级，子model不要写优先级，优先级是主model维度的值


### 阶段二：共享组件动态瀑布流分配 (Waterfall Allocation)
1. 建立全局虚拟库存池：
   入池条件（按初始值判断一次）：独立站渠道库存ₙ > 0
   可用库存ₙ = min( 独立站渠道库存ₙ , 海外仓库存总量ₙ )

2. 按阶段一的主 model 营收优先级依次遍历：
   ① 该主 model 的清库范围组件 = { 子modelₙ | 独立站渠道库存ₙ > 0 }
   ② 范围为空（子model渠道库存全为 0）→ K = 0，跳过该主 model
   ③ K = minₙ∈范围组件 ( 可用库存ₙ )
      无子model的单一主记录：同样按自身 独立站渠道库存 > 0 判断是否入池
   ④ 扣减（两池同时减 K，保证 min 口径一致）：
      独立站渠道库存ₙ = 独立站渠道库存ₙ − K
      海外仓库存总量ₙ = 海外仓库存总量ₙ − K
   ⑤ 记录该主 model 的齐套数 K

### 阶段三：长版识别与强锁报废 (Long-board Scrap Logic)
1. 遍历分配完毕后 `Virtual_Stock_Pool` 中所有剩余数量大于 0 的组件。
2. 标记该剩余数量为“长版死库存 (Unmatched Long-board)”。
3. 强制对长版库存施加方案：`组件报废`，计算报废损失：
   Scrap_Cost = SUM( Remaining_Stock_i × Unit_Scrap_Cost_i )

   其中，组件 i 的单件报废成本 Unit_Scrap_Cost_i 计算如下：
   Unit_Scrap_Cost_i = （采购价 + 头程）_i + 报废处理费_i

   报废处理费_i 按组件单品重量（磅）分档：
   - 单品重量 < 50 磅：$2.00 / 件
   - 单品重量 ≥ 50 磅：$3.00 / 件

### 阶段四：齐套成品的混合清库分配与财务核算 (Scenario Evaluation)

> **变更说明**：原「三选一 MAX(方案A, B, C)」不再作为决策依据 —— 方案 A 单价最高必然胜出，但**实际不一定卖得掉**。
> 现改为**双口径并列输出**：
> - **4.1 全量 K 并列测算**：假设 K 套全部按单一方案卖出，供领导层看理想上限与方案横向对比 —— **保留，仅作参考**。
> - **4.2–4.5 混合分配**：按真实可销量切分 K，并对本轮卖不掉的部分计提 —— **决策依据**。

#### 4.0 各方案单件净回收额（u，单位：元/套）
- **方案 A (降价卖)**: u_A = 降价售价 - 变动销售费用 - 推广费
  - 变动销售费用 = 固定成本合计
  - 推广费 = 降价售价 × 30%
- **方案 B (线下清库 1-2 折)**: u_B = (原价 × 折扣率) - (采购价+头程)
- **方案 C (激励方案)**:
  - 营业收入 = 该方案清库套数 × 售价 × 0.8（8 折促销售价）
  - ⚠️ 该营业收入**不属于本渠道收入，已剔除**（本渠道收入记 0）
  - 本渠道净回收 = 0 − 运营团队奖金（通常为负值；方案 C 的价值体现在消化库存、减少未清库量与计提损失）
  - 奖金按「呆滞采购金额」分档计提，上限 1 万美金 / 半年 / 运营团队：

    | 呆滞采购金额 (USD) | 奖金（正常提成之外） | 计算公式 |
    |---|---|---|
    | ≤ 20万 | 营业收入的 1% | 营业收入 × 1% |
    | > 20万, ≤ 50万 | 营业收入的 1.5% | (营业收入 − 20万USD) × 1.5% + 20万USD × 1% |
    | > 50万 | 营业收入的 2% | (营业收入 − 50万USD) × 2% + 30万USD × 1.5% + 20万USD × 1% |
  

#### 4.1 全量 K 并列测算（理想上限 · 汇报视角）
> 保留「假设 K 套全部按单一方案卖出」的并列测算，用于领导层查看各方案的**理想上限**与**横向对比**。
> ⚠️ 此口径**不考虑能否真的卖出**，仅供参考，**不作为决策依据**（决策以 4.2–4.5 混合分配结果为准）。

| 方案 | 单件净回收 u | 全量 K 净回收额 |
|---|---|---|
| A 降价卖 | u_A | `K × u_A` |
| B 线下清库 1-2 折 | u_B | `K × u_B` |
| C 激励方案 | u_C = 0（本渠道收入已剔除） | `0 − 运营团队奖金`（奖金按 K 套营业收入计） |

- `Path* = MAX( K × u_A , K × u_B , − 运营团队奖金 )`：三者中的最优**单一**方案，即理想上限
- 若三者回收额均为负数且不及报废，则该齐套成品退化为整套报废
- 输出时三个方案的净回收额**全部并列呈现**，不隐藏劣选方案

#### 4.2 可销量测算（销量基准 + 降价放大）
1. **基准销量** `S30` = 过去 30 天销量（主 model 维度）
2. **折扣深度** `d = (原价 − 实际售价) / 原价`
3. **放大系数** `M = clamp(1 + λ × d, 1.0, 3.0)`
   - 保守取值 **λ = 1.0**（打 8 折 → 1.2 倍；打 5 折 → 1.5 倍；打 3 折 → 1.7 倍）
   - 上限 3.0（防止深度折扣无限放大），下限 1.0
4. **该售价下的累计可销量** `Q = ⌊S30 × M⌋`（向下取整，保守）

#### 4.3 混合分配（需求分层瀑布）
三个方案共享同一批需求，**不能用 ΣQ 相加**，只能按价格从高到低取增量：
1. 按**实际售价从高到低**排序三个方案（通常为 A > C > B），各自算累计可销量 Q₁ ≤ Q₂ ≤ Q₃
2. 最高价：`k₁ = min(K, Q₁)`
3. 次高价：`k₂ = min(K − k₁, Q₂ − Q₁)`
4. 最低价：`k₃ = min(K − k₁ − k₂, Q₃ − Q₂)`
5. **未清库量** `ΔK = K − (k₁ + k₂ + k₃)`：本轮卖不掉，继续积压 → 进入 4.4 计提
6. 若某层单件净回收 u < 0 且不如直接报废，该层退化为整套报废

#### 4.4 未清库计提（Provision）
未清库量 ΔK 继续积压，公司按**库龄**计提沉没成本，作为亏损计入本渠道：
- 按 BOM 折算：每套成品涉及各组件 ΔK 件，逐组件按各自库龄计提
- 单件计提规则：

  | 库龄 | 计提比例 | 单件计提额 |
  |---|---|---|
  | 121–180 天 | 30% | 采购价 × 30% |
  | 181–270 天 | 80% | 采购价 × 80% |
  | > 270 天 | 150% | 货值 × 150% |

- `计提费用 = Σ_组件 ( ΔK × 单件计提额 )`
- ⚠️ 跨周期会重复计提（同一批库存下一周期按新库龄再次计提），本模型不做去重，按公司规则照计。
- ⚠️ 「货值」口径待确认，暂按账面货值 = 采购价处理。

#### 4.5 本渠道净额
`本渠道净额 = (k_A × u_A) + (k_B × u_B) − 运营团队奖金_C − 计提费用`

#### 4.6 本阶段新增输入字段（建议补入 2.1）
- 过去 30 天销量（主 model 维度）
- 库龄（天）（子 model / 组件维度）
- 采购价（不含头程）--- 计提基数，需从 2.1 的「采购价+头程」中拆分

##5. System Prompt (智能体核心系统提示词)
你是一个专业的供应链运筹与清库财务精算 Agent（BOM-ClearAgent）。你的任务是帮用户解决带有“共用组件”约束的产品清库核算问题。
###你必须严格遵守以下业务法则：

1.严格防范“虚拟库存重叠”：共享组件同一时间只能分配给一个产品，不能重复计算。
2.绝对的长版报废隔离：组件分配结束后，任何无法凑成完整单套的剩余组件，必须且只能标记为“组件报废”，绝不能计入降价或线下清库路径。
3.动态优先级响应：在分配共享组件前，必须确认用户的清库优先级（例如：是优先保高单价产品现金流，还是优先清理积压件数最多产品）。
4.财务最优解输出：对于齐套部分，必须逐一对比降价卖、线下清库、激励方案的净回收资金，给出数学上最优的方案推荐。

###输出要求：

1.结构清晰，明确区分【齐套清库方案】与【长版报废方案】。

2.给出清晰的计算汇总表（包含总回收资金、总报废成本、净收益）。
