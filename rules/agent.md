# agent.md: 库存清库与 BOM 约束分配智能体规范

## 1. 智能体定位 (Role & Goal)
- **Agent 名称**: BOM-ClearAgent (库存清库与 BOM 约束决策智能体)
- **定位**: 跨供应链与财务测算的运筹决策 AI
- **核心目标**: 
  1. 解析产品与组件的 BOM 映射及共享组件库存。
  2. 依据过去30天销量与价格分配权重，对齐套成品进行多方案财务比对。
  3. 自动剥离无法齐套的“长版库存”并强制标记为“组件报废”。并核算报废成本。
  4. 对齐套成品测算【降价卖】、【线下清库（1-2折）】、【激励方案】三种路径的净回收额与成本，推荐最佳清库策略组合。

## 3. 核心算法流程 (Agent Workflow)

### 阶段一：BOM 解构与经济参数准备
1. 对于各个有子model的主model，识别共用的子model，把共用一个子model的主model分为一组，为后续该子model库存优先级分配的范围
2. 展示排序（仅用于报表排名）：
用过去30天的营收来算每一个主model的优先级，子model不要写优先级，优先级是主model维度的值
3. 预计算各主model经济参数：u_A、u_B、Q_A（见阶段四 4.0/4.2 口径），供阶段二贪心比价使用


### 阶段二：共享组件边际价值贪心分配 (Value-Greedy Allocation, 2026-09-16 拍板)
> 取代旧「按营收排序瀑布流」。营收高 ≠ 每件稀缺组件的净回收高；实测旧规则在共享组件稀缺时把钱分错（负毛利单件 model 吃掉组件，高价值 BOM model 被饿死）。

1. 建立全局物理库存池：
   入池条件（按初始值判断一次）：独立站渠道库存ₙ > 0
   可用库存ₙ = min( 独立站渠道库存ₙ , 海外仓库存总量ₙ )

2. 逐套贪心比价：每一套齐套名额分配给「单套边际价值」最高的主model
   - 单套边际价值 = 最优可行路径净回收 + 整套BOM避免的报废成本
     - 路径净回收：该主model已分配套数 k < Q_A 且 u_A > 0 时取 u_A（A段容量内），否则取 u_B（B段兜底）
     - 避免报废成本 = Σ该BOM各组件 (采购价+头程 + 报废处理费)；「清库标记=不清库」的组件计 0
   - 边际价值 ≤ 0 的主model不凑套：把组件留在池中走报废更优（不制造负毛利齐套）
   - 同分决胜：营收高者优先，再按 model 名排序保证确定性
3. 每分配一套按 FIFO 扣减（独立站批次优先，不足借非独立站批次 —— borrow 模式口径；扣减在同一物理池内操作，杜绝超分配）
4. 组件池耗尽或所有可行主model边际价值 ≤ 0 时结束；剩余组件进入阶段三长版报废
5. 输出「稀缺组件取舍明细」：对每个耗尽的共享组件，记录赢家（拿了多少套）与让位者（被饿死的model），供业务复核

### 阶段三：长版识别与强锁报废 (Long-board Scrap Logic)
1. 遍历分配完毕后 `Virtual_Stock_Pool` 中所有剩余数量大于 0 的组件。
2. 标记该剩余数量为“长版死库存 (Unmatched Long-board)”。
3. 强制对长版库存施加方案：`组件报废`，计算报废损失：
   Scrap_Cost = SUM( Remaining_Stock_i × Unit_Scrap_Cost_i )

   其中，组件 i 的单件报废成本 Unit_Scrap_Cost_i 计算如下：
   Unit_Scrap_Cost_i = （采购价 + 头程）_i + 报废处理费_i

   报废处理费_i 按组件单品重量（磅）分档：
   - 单品重量 < 50 磅：$2.00 / 件
   - 单品重量 ≥ 50 磅：$3.00 / 件

### 阶段四：齐套成品的混合清库分配与财务核算 (Scenario Evaluation)

> **变更说明**：原「三选一 MAX(方案A, B, C)」不再作为决策依据 —— 方案 A 单价最高必然胜出，但**实际不一定卖得掉**。
> 现改为**双口径并列输出**：
> - **4.1 全量 K 并列测算**：假设 K 套全部按单一方案卖出，供领导层看理想上限与方案横向对比 —— **保留，仅作参考**。
> - **4.2–4.5 混合分配**：按真实可销量切分 K，并对本轮卖不掉的部分计提 —— **决策依据**。

#### 4.0 各方案单件净回收额（u，单位：元/套）
- **方案 A (降价卖)**: u_A = 降价售价 - 变动销售费用 - 推广费
  - 变动销售费用 = 固定成本合计
  - 推广费 = 降价售价 × 30%
- **方案 B (线下清库 1-2 折)**: u_B = (原价 × 折扣率) - (采购价+头程)
- **方案 C (激励方案)**:
  - 营业收入 = 该方案清库套数 × 售价 × 0.8（8 折促销售价）
  - ⚠️ 该营业收入**不属于本渠道收入，已剔除**（本渠道收入记 0）
  - 本渠道净回收 = 0 − 运营团队奖金（通常为负值；方案 C 的价值体现在消化库存、减少未清库量与计提损失）
  - 奖金按「呆滞采购金额」分档计提，上限 1 万美金 / 半年 / 运营团队：

    | 呆滞采购金额 (USD) | 奖金（正常提成之外） | 计算公式 |
    |---|---|---|
    | ≤ 20万 | 营业收入的 1% | 营业收入 × 1% |
    | > 20万, ≤ 50万 | 营业收入的 1.5% | (营业收入 − 20万USD) × 1.5% + 20万USD × 1% |
    | > 50万 | 营业收入的 2% | (营业收入 − 50万USD) × 2% + 30万USD × 1.5% + 20万USD × 1% |
  

#### 4.1 全量 K 并列测算（理想上限 · 汇报视角）
> 保留「假设 K 套全部按单一方案卖出」的并列测算，用于领导层查看各方案的**理想上限**与**横向对比**。
> ⚠️ 此口径**不考虑能否真的卖出**，仅供参考，**不作为决策依据**（决策以 4.2–4.5 混合分配结果为准）。

| 方案 | 单件净回收 u | 全量 K 净回收额 |
|---|---|---|
| A 降价卖 | u_A | `K × u_A` |
| B 线下清库 1-2 折 | u_B | `K × u_B` |
| C 激励方案 | u_C = 0（本渠道收入已剔除） | `0 − 运营团队奖金`（奖金按 K 套营业收入计） |

- `Path* = MAX( K × u_A , K × u_B , − 运营团队奖金 )`：三者中的最优**单一**方案，即理想上限
- 若三者回收额均为负数且不及报废，则该齐套成品退化为整套报废
- 输出时三个方案的净回收额**全部并列呈现**，不隐藏劣选方案

#### 4.2 可销量测算（销量基准 + 降价放大）
1. **基准销量** `S30` = 过去 30 天销量（主 model 维度）
2. **折扣深度** `d = (原价 − 实际售价) / 原价`
3. **放大系数** `M = clamp(1 + λ × d, 1.0, 3.0)`
   - 保守取值 **λ = 1.0**（打 8 折 → 1.2 倍；打 5 折 → 1.5 倍；打 3 折 → 1.7 倍）
   - 上限 3.0（防止深度折扣无限放大），下限 1.0
4. **该售价下的累计可销量** `Q = ⌊S30 × M⌋`（向下取整，保守）

#### 4.3 混合分配（需求分层瀑布）
三个方案共享同一批需求，**不能用 ΣQ 相加**，只能按价格从高到低取增量：
1. 按**实际售价从高到低**排序三个方案（通常为 A > C > B），各自算累计可销量 Q₁ ≤ Q₂ ≤ Q₃
2. 最高价：`k₁ = min(K, Q₁)`
3. 次高价：`k₂ = min(K − k₁, Q₂ − Q₁)`
4. 最低价：`k₃ = min(K − k₁ − k₂, Q₃ − Q₂)`
5. **未清库量** `ΔK = K − (k₁ + k₂ + k₃)`：本轮卖不掉，继续积压 → 进入 4.4 计提
6. 若某层单件净回收 u < 0 且不如直接报废，该层退化为整套报废

#### 4.4 未清库计提（Provision）
未清库量 ΔK 继续积压，公司按**库龄**计提沉没成本，作为亏损计入本渠道：
- 按 BOM 折算：每套成品涉及各组件 ΔK 件，逐组件按各自库龄计提
- 单件计提规则：

  | 库龄 | 计提比例 | 单件计提额 |
  |---|---|---|
  | 121–180 天 | 30% | 采购价 × 30% |
  | 181–270 天 | 80% | 采购价 × 80% |
  | > 270 天 | 150% | 货值 × 150% |

- `计提费用 = Σ_组件 ( ΔK × 单件计提额 )`
- ⚠️ 跨周期会重复计提（同一批库存下一周期按新库龄再次计提），本模型不做去重，按公司规则照计。
- ⚠️ 「货值」口径待确认，暂按账面货值 = 采购价处理。

#### 4.5 本渠道净额
`本渠道净额 = (k_A × u_A) + (k_B × u_B) − 运营团队奖金_C − 计提费用`

#### 4.6 本阶段新增输入字段（建议补入 2.1）
- 过去 30 天销量（主 model 维度）
- 库龄（天）（子 model / 组件维度）
- 采购价（不含头程）--- 计提基数，需从 2.1 的「采购价+头程」中拆分

##5. System Prompt (智能体核心系统提示词)
你是一个专业的供应链运筹与清库财务精算 Agent（BOM-ClearAgent）。你的任务是帮用户解决带有“共用组件”约束的产品清库核算问题。
###你必须严格遵守以下业务法则：

1.严格防范“虚拟库存重叠”：共享组件同一时间只能分配给一个产品，不能重复计算。
2.绝对的长版报废隔离：组件分配结束后，任何无法凑成完整单套的剩余组件，必须且只能标记为“组件报废”，绝不能计入降价或线下清库路径。
3.动态优先级响应：在分配共享组件前，必须确认用户的清库优先级（例如：是优先保高单价产品现金流，还是优先清理积压件数最多产品）。
4.财务最优解输出：对于齐套部分，必须逐一对比降价卖、线下清库、激励方案的净回收资金，给出数学上最优的方案推荐。

###输出要求：

1.结构清晰，明确区分【齐套清库方案】与【长版报废方案】。

2.给出清晰的计算汇总表（包含总回收资金、总报废成本、净收益）。

## 阶段二优化：共享组件边际价值贪心分配（2026-09-16 晚拍板）

### 背景与问题
问题一、二修复后（单物理池杜绝超分配 + 报废单行挂载），暴露出新的决策问题：**共享部件在多个主model间稀缺时，到底该让谁凑套、让谁让位报废？** 旧规则（按30天营收排序瀑布流）的隐式取舍实测把钱分错：

| 稀缺组件 | 旧算法赢家(单套边际值) | 被饿死者(单套边际值) | 结论 |
|---|---|---|---|
| AMBFC04NR-C1-US (51件) | AMBFC04NR-C1-US ($85.02) | AMBFC04NR-V-US ($183.70) | 给错人，差 $98.68/套 |
| AMBFC04NR-C2-US (125件) | AMBFC04NR-C2-US ($95.87) | AMBFC04NR-V-US ($183.70) | 给错人，差 $87.83/套 |
| HNESD217W-US (1件) | HNESD213LW ($130.65) | HNESD216LW ($166.78) | 给错人，差 $36.13/套 |

根因：**营收高 ≠ 每件稀缺组件的净回收高**。AMBFC04NR-C1/C2 是无 BOM 的单件 model，u_b 为负（-$18.78/-$14.02，1.5折出清仍亏采购+头程），却因营收排名吃掉全部稀缺组件；AMBFC04NR-V（440刀 BOM 成品，u_b=+$66）被饿死。

### 新规则：边际价值贪心（Value-Greedy）
逐套比价分配：每一套齐套名额给「单套边际价值」最高的主model。

```
单套边际价值 = 最优可行路径净回收 + 整套BOM避免的报废成本
  路径净回收: 该model已分配 k 套
    k < Q_A 且 u_A > 0  →  取 u_A   (A段容量内, 8折真实可卖)
    否则                  →  取 u_B   (B段兜底价)
  避免报废成本 = Σ各组件(采购价+头程+报废处理费)
    「清库标记=不清库」组件计 0
```

- **边际价值 ≤ 0 的 model 不凑套**：把组件留在池中走报废更优，不制造负毛利齐套
- **销量感知**：零销量 model（S30=0 → Q_A=0）第一套就按 u_B 估值，不会被高估能卖高价
- **同分决胜**：营收高者优先，再按 model 名排序，保证结果确定性
- **借调口径**（前端插件 borrow 模式）：还需至少一个组件有独立站批次（与旧瀑布一致）；扣减时独立站批次优先，不足借非独立站，同一物理池操作
- 营收排序保留但降级为**展示排名**，不再决定分配先后

## 阶段三优化：单件综合成本细化与阶梯累进仓储费核算（2026-09-17）

### 背景与重构动因
旧版成本模型使用单一的「固定成本合计」或「采购成本(第一批)」，无法真实反映不同库龄批次的持有成本差异，且缺失了头程、尾程、关税与仓储费的细粒度拆解。

第三轮优化彻底**废弃旧「固定成本合计」字段**，重构为：
$$\text{单件综合成本} = \text{采购价} + \text{头程运费} + \text{尾程运费} + \text{关税} + \text{仓储费}$$

### 核心规则与业务口径

#### 1. 细粒度成本来源（以利润测算表为权威基准）
- **数据源**：从利润测算表中按 Item 提取 `采购价(buy)`、`头程运费(head)`、`关税(tariff)`、`尾程运费(last)` 以及长宽高尺寸（计算 CBM）。
- **兜底回退机制**：若利润表缺失或小于等于0，回退取主表已有值（如 `采购价 = row.buy_price`，`头程 = row.pp_first - row.buy_price`，`尾程/关税 = 0`）。
- **BOM 组合款求和**：若主 Model 为 BOM 组合款，其各分项成本（采购/头程/关税/尾程/仓储费/CBM）为**所有子组件按用量配比的物理累加之和**。

#### 2. 阶梯累进仓储费（Method A / Progressive）
- **阶梯日费率标准（$/m³/天）**：
  | 库龄区间（天） | 费率（$/m³/天） |
  |---|---|
  | 0 – 60 天 | $0.00（免费期） |
  | 61 – 90 天 | $0.25 |
  | 91 – 180 天 | $0.78 |
  | 181 – 360 天 | $0.90 |
  | > 360 天 | $1.25 |

- **累进计费逻辑**：若批次当前库龄为 $A$，预测未来持有 $\Delta D$ 天，按天累进计费：
  $$\text{单件增量仓储费} = \text{CBM} \times \sum_{d=\lfloor A \rfloor}^{\lfloor A + \Delta D \rfloor - 1} \text{TierRate}(d)$$
  *例如*：100天库龄批次持有 10 天，按 91~180 天阶梯日费率 $0.78 逐日累加后乘以件体积 CBM。

#### 3. 仓储费时间窗口约束（不核算历史已结仓储费）
- **上月已结不扣**：仅核算本月及以后未来天数的增量仓储费（历史已结费用已入财务旧账，不重复计入本次清库边际扣减）。
- **方案 A（线上促销）**：持有窗口按测算窗口 $W$ 天（默认 60 天）逐日累进计费。
- **方案 B（线下批发）/ 方案 C（内部激励）**：核算时间统一按「**本月已过天数 + 10 天**」（即 $D_{\text{day}} + 10$ 天，如 17 号运行则按 27 天）逐日累进计费。

#### 4. 4 选项边际价值闭环
- **方案 A 净回收**：$u_A = \text{Price}_A - (\text{Buy} + \text{Head} + \text{Tariff} + \text{Last} + \text{Storage}_A) - \text{Price}_A \times \text{PromoRate}$
- **方案 B 净回收**：$u_B = (\text{Price}_{\text{base}} \times \text{Discount}_B) - (\text{Buy} + \text{Head} + \text{Tariff} + \text{Storage}_B)$（无尾程）
- **方案 C 净回收**：$u_C = \text{Price}_C - (\text{Buy} + \text{Head} + \text{Tariff} + \text{Last} + \text{Storage}_C) - \text{Bonus}$
- **方案 D（报废）**：长版/无法凑套组件单件损失 $\text{Loss} = \text{Buy} + \text{Head} + \text{ScrapFee}$（仍按批次实际消耗计入总报废额）

1. **Python 核心计算链**：
   - 新增 `src/cost_helper.py`（提供 `tier_rate`、`calc_incremental_storage_fee`、`CostProvider`）

## 第四轮优化：在途库存 + 工厂未发货库存（2026-09-17）

### 业务口径（用户拍板；2026-09-18 架构修正：输入字段迁移至主表，见文末）
1. **在途库存**：人工填写《清库方案成本核算》主表「在途库存」(flddngbOgM) + 「在途到货时间(天)」(fldiImmyEV)——BOM 款填子记录行，单件款填主记录行。

   - **到货时间参与计算（gating）**：仅到货时间 ≤ 销售窗口期 W（当前 60 天）的在途才入池；到货晚于窗口或到货时间未填写的在途不参与本轮（保守排除）。
2. **工厂未发货库存**：人工填写《清库方案成本核算》主表「工厂未发货数量」(fldETydQ9I)，model 维度（BOM 款各子件行分别填，决策按子件最小值对齐）。
   - 决策问题：这批未发货订单发不发？发货 → 按 A/B/C 最优路径测算单套净回收；不发货 → 亏损采购价（Σ未发件 × 采购价）。
   - **整数倍约束**：候选发货量 X ∈ {0, ⌊F/2⌋, F}——整单全发、最多除以2发、或不发；不能任意拆散（用户口径："最多就除以2发"）。
   - BOM 款：F = 各子件未发货量的最小值（各子件必须同数量齐套发）；任一子件未填写 → 无法决策，写回 ⚠️ 提示。
   - 单件款：F = 该主记录行的未发货量。

### 决策数学
```
V(X) = X × u_ship − Σᵢ (Fᵢ − X) × buyᵢ
  u_ship = 生效最优路径单套净回收（发货落地成本 = 采购+头程+关税, 库龄0起算仓储费, 无尾程按路径）
  取 V 最大的候选 X; X=0 时决策="不发货(亏采购价)"
```
验证用例（单件 F=200, buy=42）：
- u_ship=+50 → V(0)=-8400, V(100)=+800, V(200)=+10000 → **全发**
- u_ship=-5（低亏<采购价）→ V(200)=-1000 > V(0)=-8400 → **全发**（亏得比不发少）
- u_ship=-60（亏>采购价）→ V(200)=-12000 < V(0)=-8400 → **不发**

## 第五轮优化：最优窗口扫描纳入持有期计提增量（2026-09-17）

### 背景与问题
- 4.7 最优窗口扫描 `eval_options(W)` 中净额只含「窗口 W 增量仓储费 + A/C 可卖量 + B 出清」，**计提恒为 0**（四个选项均假设 K 套全部处置，ΔK=0）。

## 幽灵库存事故修复：跨快照缓存 + 校验硬拦截（2026-09-17）

## MSESD52N-V-US 齐套数为 0 事故修复：Python 链路缺 borrow 借调口径（2026-09-17）

### 事故
