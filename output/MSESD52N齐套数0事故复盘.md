## 2. 根本原因（口径分裂，非数据问题）

**规则拍板的口径（rules/agent.md 阶段二，2026-09-16）**：
- 组件池 = 海外仓**全量**批次（borrow 模式），每批次带 `is_dtc` 归属标记
- 分配门槛：整套 BOM 至少一个组件有独立站批次（杜绝纯借调套利）
- 扣减：独立站批次优先（FIFO），不足借非独立站，同一物理池

**实际实现**：
- ✅ 前端插件 `plugin_app/src_app.js`（线上口径）：完整实现（L172-204 入池、L362-401 门槛+借调扣减）
- ❌ Python 链路 `src/fetch_inventory.py` L180-182：入池硬编码 `所属团队 == "独立站"` 过滤，非独立站批次全部排除
- ❌ Python 链路 `src/allocation.py`：无 is_dtc 概念；头注释声称「borrow 模式口径，与前端插件一致」但代码从未兑现

**因果链**：
```
MSESD41W-US 的 345 件库存全部在 Amazon-VC/SC/Wayfair（非独立站团队）
→ 严格独立站入池 → 41W 池内 = 0 件
→ BOM 凑套需要所有子件（41W + 52N 各 1 件/套）
→ 贪心循环 `any(pool[n] <= 0) → continue` 直接跳过该 model
→ MSESD52N-V-US K=0，52N 的 50 件独立站库存全部滞留进入长版报废
```

**影响面**：不止这一个 model——所有「跨渠道库存挂账」的组件在 Python 链路被系统性低估齐套能力。总 K 从旧口径 1002 → 修复后 1041。
