清库方案自动计算 — 算法流程图与说明

版本 v2026.09.17 ｜ 分配引擎：边际价值贪心（2026-09-16 拍板）｜ 数据源：飞书多维表格《清库方案成本核算》+《库存表》｜ 本文档数字为 2026-09-16 全量真实运行结果
一句话概括：从 BOM 与行级批次库存出发，用「单套边际价值 = 最优路径净回收 + 避免的整套报废成本」逐套比价，把每一套齐套名额分给价值最高的主 model；分不到套的组件剩余强锁报废；齐套部分在 A 促销 / B 线下出清 / C 激励 / 组合四选项中按真实可销量做净额比选，输出每 model 的具体动作（方案+套数+净额+最优窗口期）并写回飞书。

三、阶段二详解：边际价值贪心（核心）

2026-09-16 拍板，取代旧「按30天营收排序瀑布流」。根因：营收高 ≠ 每件稀缺组件的净回收高，旧规则把钱分错了。

单套边际价值 v(model) = 路径净回收 + Σ(n ∈ BOM范围) 单件报废成本(n) 路径净回收： 已分配套数 k < Q_A 且 u_A > 0 → u_A （A段容量内，8折真实可卖） 否则 → u_B （B段1.5折兜底价） 单件报废成本(n) = (采购价+头程) + 报废处理费(<50lb $2 / ≥50lb $3) 「清库标记=不清库」组件计 0；数据缺失计 0（不阻塞分配） 单一主记录（无子model）：范围 = 自身，即单件 model 同样参与比价
  • v ≤ 0 不凑套：把组件留在池中走报废更优，不制造负毛利齐套（砍掉了旧算法 94 套负毛利兜底）
  • 销量感知：零销量 model（S30=0 → Q_A=0）第一套就按 u_B 估值，不会被高估能卖高价
  • 同分决胜：营收高者优先，再按 model 名排序，结果确定可复现
  • 杜绝超卖：所有扣减在同一物理池内操作（旧版双池影子拷贝曾导致同一批库存被扣两次）
  • 循环设有 200 万次安全上限，防止死循环

四、阶段四详解：四选项净额比选 + 最优窗口

4 个候选选项（对每个有齐套 K 的主 model）

选项构成净额
① A促销 + 剩余Bk_A = min(K, Q_A)（u_A>0 才启用A段）；其余走 Bk_A·u_A + (K−k_A)·u_B
② A促销 + 剩余C+BA 段同上；剩余中 k_C = min(剩余, Q_C) 走 C，再剩余走 Bk_A·u_A − 奖金(k_C) + (K−k_A−k_C)·u_B
③ 全量BK 套全部线下出清K·u_B
④ 全量C + B兜底k_C = min(K, Q_C) 走 C，其余走 B−奖金(k_C) + (K−k_C)·u_B

净额最高者胜（并列取排序前者）；输出为具体动作描述，如 A促销(2套)+B出清(49套)，零数量分段自动省略。

可销量与最优窗口

Q(售价) = ⌊ S30 × (W / 30) × M ⌋ M = clamp(1 + λ × 折扣深度, 1.0, 3.0)，λ=1.0 · 8折 → M=1.2；折扣越深放大越大，上限 3.0（保守） · 窗口 W 默认取参数表「销量预测窗口」= 60 天 · 最优窗口 W*：W 从 1 到 730 逐日扫描，取净额最大（并列取最小 W）； 净额对窗口不敏感的 model 输出空值；全局最优窗口 = 各 model W* 的众数

八、已知边界与待定参数

  • B 段收货上限：当前假设线下渠道无限收货；若有实际上限，可参数化为 Q_B 容量（与 Q_A 同构），超限部分自动改判报废 —— 待业务给数
  • 贪心为局部最优：逐套比价非全局整数规划最优；当前规模（83 主model / 1,002 套）下与全局最优差距可忽略
  • 计提跨周期不去重：同一批库存下一周期按新库龄再次计提，按公司规则照计
  • 参数回退：参数表不可用或无启用行时回退代码默认值（与历史拍板值一致），运行日志会标注场景名
